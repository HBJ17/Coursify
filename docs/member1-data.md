# Member 1: Data & Catalog

Owner of the database layer (Oracle JDBC), the course catalog and login.

## Classes

| Class | Package | What it does |
|---|---|---|
| `DBConnectionManager` | `util` | Singleton. Reads `db.properties` once, hands out connections. |
| `StudentDAOImpl`, `AdminDAOImpl` | `dao.impl` | Read (and for students, save) users; `findCompletedCourses` reads `completed_courses`. |
| `CourseDAOImpl` | `dao.impl` | Reads courses with prerequisites and time slots; saves/updates/deletes in one transaction; loads the prerequisite graph. |
| `RegistrationDAOImpl` | `dao.impl` | `registerAtomic` and `cancelAtomic` (transactions) and the active-registration queries. |
| `WaitlistDAOImpl` | `dao.impl` | Waitlist add/remove/find; joins `students` to get each entry's CGPA. |
| `CourseServiceImpl` | `service.catalog` | Catalog with `HashMap` lookup and `TreeMap` sorted view. |
| `AuthServiceImpl` | `service.catalog` | Login for students first, then admins. |

## Schema (`database/schema.sql`)

```
students(student_id PK, name, email, password, cgpa)
admins(admin_id PK, name, email, password)
courses(course_code PK, title, credits, capacity, seats_left, waitlist_cap, class_day, start_time, end_time)
prerequisites(course_code FK, prereq_code FK)          -- PK is the pair; this is the graph's edge list
completed_courses(student_id FK, course_code FK)
registrations(reg_id PK identity, student_id FK, course_code FK, status, reg_time)
waitlist(waitlist_id PK identity, student_id FK, course_code FK, joined_time)  -- UNIQUE(student_id, course_code)
```

Oracle specifics:
- No `ENUM` or `TIME` type. `class_day` is `VARCHAR2` with a `CHECK` (maps to `DayOfWeek.valueOf`), and
  `start_time` / `end_time` are `'HH:mm'` text (`LocalTime.parse` / `toString()`). A `NULL` day means the course has no fixed `TimeSlot`.
- IDs come from `GENERATED BY DEFAULT AS IDENTITY`. After an insert we read the ID with
  `prepareStatement(sql, new String[]{"REG_ID"})` and `getGeneratedKeys()`, because Oracle does not reliably support `RETURN_GENERATED_KEYS`.
- `ON DELETE CASCADE` means deleting a course also removes its prerequisite, registration and waitlist rows.
- `CHECK (seats_left >= 0)` is a second line of defence against overbooking.

## Transactions

A transaction is a group of SQL statements that either **all** take effect or **none** do (ACID).
In JDBC: `setAutoCommit(false)`, run the statements, then `commit()`; on any error `rollback()`.
`finally` puts auto-commit back, because connections are closed rather than pooled but the habit keeps the code safe.

`registerAtomic`:
1. `UPDATE courses SET seats_left = seats_left - 1 WHERE course_code = ? AND seats_left > 0`
   If it changed 0 rows there is no seat: roll back and throw `DatabaseOperationException("No seats left in ...")`.
2. `INSERT` the registration and read back its generated `reg_id`.
3. `commit()`.

The `seats_left > 0` test and the decrement are ONE statement, so two students clicking at the same moment cannot both
take the last seat: Oracle locks the row, and the second `UPDATE` sees `seats_left = 0` and changes nothing.

`cancelAtomic`: mark the `ACTIVE` row `CANCELLED` (0 rows changed means there was nothing to cancel, so throw), then `seats_left + 1`, then commit.

`CourseDAOImpl.save/update/delete` use the same pattern so a course row and its prerequisite rows are never half-written.

## Singleton (`DBConnectionManager`)

- Private constructor, one `static` instance, `getInstance()` is `synchronized` (thread-safe).
- The constructor loads `/db.properties` from the classpath once. If it is missing it throws
  `DatabaseOperationException` with a message that says what to do.
- `getConnection()` returns a **new** connection each time; callers close it with try-with-resources.
- Why a Singleton: the settings are loaded and validated in exactly one place, and no class can create a second, differently configured manager.

## Other design points

- **DAO pattern**: services and the UI only know the interfaces in `com.crs.dao`. The Oracle classes and the in-memory fakes are interchangeable.
- **PreparedStatement everywhere**: values are bound with `?`, which prevents SQL injection and handles quoting.
- **try-with-resources everywhere**: `Connection`, `PreparedStatement` and `ResultSet` are always closed, even on errors.
- **Exception translation**: every `SQLException` becomes an unchecked `DatabaseOperationException` with a readable message.
- **`CourseServiceImpl`**: `HashMap<String, Course>` gives O(1) lookup by code; `TreeMap<String, Course>` keeps courses sorted by code.
  Both are rebuilt from `courseDAO.findAll()` on every read so seat counts are never stale.
- **`AuthServiceImpl`**: one error message for "unknown ID" and "wrong password", so a caller cannot tell which IDs exist.
- **Prerequisite graph**: `loadPrerequisiteGraph()` returns an adjacency list (`Map<String, List<String>>`), used by Member 2's prerequisite rule.

## Setup and tests

1. As SYSTEM run `database/00_create_user.sql`, then as `crs` run `database/schema.sql`.
2. Copy `src/main/resources/db.properties.example` to `db.properties` (git-ignored) and check the service name.
3. `mvn test`. `CourseServiceImplTest` and `AuthServiceImplTest` always run (in-memory DAOs).
   `OracleDaoTest` runs only when `db.properties` exists; otherwise it is skipped. It uses a temporary course `TST99` and deletes it afterwards.
